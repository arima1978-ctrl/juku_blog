# ダッシュボード「SEO効果測定」タブ 提案 — DRAFT・未承認

## 目標

10/25のプレゼンでそのまま画面共有できる品質。校舎別・時系列で「実施群だけが動いた」ことを
視覚的に示せることを最優先とする。対象週は常に「先週(完全な週)」のみ(不完全な週は表示しない)。

## 画面構成

1. 校舎切り替え(既存ダッシュボードの校舎トグルを流用)
2. 表示回数/クリックの時系列(積み上げ棒グラフ: ブログ/校舎ページ/その他の3区分。
   「その他」は薄い色でサイト全体の参考値として表示し、主役の2区分と視覚的に区別する)
3. ギャップ充足率の時系列(折れ線、%表示)
4. キーワード別順位推移(折れ線、複数キーワード重ね描き。Y軸は順位なので**上が1位**になるよう反転)。
   キーワードごとに`implemented_at`の週で縦線マーカーを入れ、「実施後に順位が動いたか」を
   一目で示す(10/25プレゼンの核)
5. キーワード選択UI(全件は多すぎるため、実施済みのキーワードを既定で選択、任意に追加可能)

## 技術方針

- 既存`dashboard.html`は素のHTML/CSS/vanilla JS(ビルドステップ無し)。グラフ描画には
  軽量なChart.js(CDN読み込み1行)を追加する案を推奨(自前SVG実装より大幅に工数を削減でき、
  プレゼン向けの見た目も安定している)
- 新規バックエンドAPI: `GET /api/seo/metrics-snapshots?branchId=<id>` (校舎合計の時系列)、
  `GET /api/seo/metrics-keyword-snapshots?branchId=<id>&keywords=<comma区切り>` (キーワード別時系列)
  ——いずれも既存の`seo_metrics_snapshots`/`seo_metrics_keyword_snapshots`を返すだけの読み取り専用

## フェーズ分割と工数見積り

| フェーズ | 内容 | 見積り |
|---|---|---|
| 1. API基盤 | 上記2エンドポイント追加、テスト | 1〜2時間 |
| 2. 基本グラフ | タブ追加・校舎切替・表示回数/クリック積み上げグラフ・充足率折れ線 | 2〜3時間 |
| 3. キーワード順位推移 | キーワード選択UI・順位折れ線(Y軸反転)・実施日マーカー | 2〜3時間 |
| 4. プレゼン仕上げ | スタイル調整・注釈・印刷/スクリーンショット向けレイアウト | 1〜2時間 |
| **合計** | | **6〜10時間(1〜2日分)** |

## 前提・リスク

- **データ量が現時点で2週分(7/13週・7/20週)のみ**。グラフとして「動き」を示すには最低でも
  数週間分の蓄積が必要。10/25まで約12週あるため時間的な余裕はあるが、実装自体は早めに終わらせて
  「グラフが正しく積み上がっていくか」を毎週確認できる状態にしておくのが望ましい
- GSC接続が今週完了したばかりのため、ブログ自体の表示回数はまだ小さい(新規ページのインデックス待ち)。
  プレゼン当日までにどれだけ「動き」が出るかはコンテンツの実施ペース次第
- フェーズ1・2を先に実装し、実データが数週間分溜まった9月頃にフェーズ3・4を仕上げる、
  という2段階の進め方も可能(先に基盤だけ作り、後から磨く)
