# 週次Telegramダイジェスト 提案 — DRAFT・未承認

## 目的

毎週月曜朝、人が実際に読むタイミングでSEO測定の要点を届ける。既存の「バッチ監視アラート」
(異常時のみ・`🚨`)とは完全に別枠とし、平常時も毎週必ず届く「定期便」として区別する
(絵文字・文面で視覚的にも区別: ダイジェストは`📊`)。

## タイミング設計

- **スナップショット記録**: 従来どおり日曜01:00(`seo_weekly_analysis.sh`)。対象は「先週(完全な週)」
- **ダイジェスト配信**: 別枠の新規cronで**月曜07:30**(日曜01:00に記録済みのデータを読むだけなので、
  スナップショット生成とは独立できる。配信に失敗してもデータには影響しない)

## 内容(簡潔に。フルレポートは`node scripts/seo_metrics_report.js`で別途取得できるため、
ダイジェストは要点のみ)

```
📊 週次SEOダイジェスト(7/20週)

【小幡校】
表示回数 24,009回(前週比-36%) / クリック455(前週比-46%)
  内訳: ブログ6 / 校舎ページ63 / その他23,892
ギャップ充足率 0% (0/58)
今週実施済みにした件数: 0件

【あま本部校】
表示回数 24,009回(前週比-36%) / クリック455(前週比-46%)
  内訳: ブログ0 / 校舎ページ48 / その他23,892
ギャップ充足率 0% (0/10)
今週実施済みにした件数: 0件

詳細: node scripts/seo_metrics_report.js
```

## 実装案

- 新規スクリプト`scripts/seo_metrics_digest.js`: `seo_metrics_report.js`のデータ組み立て
  (`buildBranchReport`)を再利用し、上記の簡潔な文面へ整形して`sendTelegram()`で送信する
  (重複抑制は既存の90分ウィンドウ機構をそのまま使う)
- 新規cron: `30 7 * * 1 cd /home/ubuntu/juku_blog && ... node scripts/seo_metrics_digest.js`
- 対象週は常にスナップショットの「最新記録」を読むだけ(先週=完全な週の前提が徹底されているため、
  ダイジェスト側で日付計算をやり直す必要はない)
- スナップショットが1件も無い(初回など)場合は「データなし」を送らず静かにスキップする
  (無意味な通知を避ける)

## 確認したい点

1. 配信時刻は月曜07:30でよいか(始業前を想定)
2. 「今週実施済みにした件数」は`implemented_at`が対象週内の値を持つタスク数(週内での新規実施数)
   を意図している。累計ではなく増分でよいか
3. キーワード別の詳細(順位など)はダイジェストには含めない(フルレポート誘導のみ)でよいか
